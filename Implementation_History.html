🛠️ Implementation History

Minecraft Mod Auto Translator (AI Powered)

v3.4 (Latest) Lite Strategy & Self-Healing
  • New Lite限定モード: --lite-only オプションを追加。レート制限対策として、軽量モデルのみに限定して動作させる機能。
  • New 自動修復機能 (Self-Healing): 起動時に出力済みファイル（ja_jp.json）とキャッシュを全スキャンし、「Error 504」などの汚染データを物理的に削除して再翻訳対象にする機能。
  • Update 優先順位の刷新: RPD（1日あたりのリクエスト数）を重視。Gemini 2.5 Lite (RPD 1000) を主力とし、Gemma 3 (RPD 14400) を「最後の砦」として配置する鉄壁の布陣へ変更。
  • New 詳細進捗可視化: ファイル単位だけでなく、内部のバッチ通信状況（Translating: 1/86）をプログレスバーで可視化し、フリーズの誤解を解消。
  • New モデルチェッカー: 引数なしで起動した際に、APIキーで利用可能なモデル一覧を表示する機能を追加。
  • Fix 429エラー対策強化: レート制限時は待機せず即座に次のモデルへスイッチし、全モデル枯渇時のみ待機するロジックに変更。
v3.3 Custom Path Support
  • New 出力先自由指定: start.bat で出力先フォルダのフルパス指定やドラッグ＆ドロップ入力に対応。デスクトップや別ドライブへの保存が可能に。
  • Fix パス表示改善: 実行ログに出力先の絶対パスを表示し、保存場所を明確化。
v3.2 Manual Selection & Project Isolation
  • Update プロジェクト別管理: キャッシュとログの保存場所を、スクリプト直下から「各出力リソースパックフォルダ内」に変更。複数プロジェクトの並行作業が可能に。
  • New 手動モデル選択モード: 自動選択に頼らず、APIキーで利用可能なモデル一覧からユーザーが直接番号で選べる機能を追加。
v3.1 Statistics & Visibility
  • New 詳細統計表示: フォルダ内の全ファイル数、Modファイル数、スキップ済み数を明確に表示し、「Mod数が合わない」問題を解決。
  • Update 探索ロジックの適正化: 再帰探索（サブフォルダ探索）を廃止し、ユーザーの期待値に近い「直下フォルダのみ」の探索に戻した。
  • Fix Mod認識修正: .jar に加えて .zip 形式のファイルも正しく認識するように修正。
v3.0 REST API & Stability Overhaul
  • Fix 通信方式の刷新 (REST API化): フリーズやクラッシュの原因となっていた公式SDK (gRPC) を廃止し、Python標準の requests を用いたREST API直接通信へ完全移行。これにより安定性が劇的に向上。
  • New モデル自動探索機能: 決め打ちのモデル名ではなく、APIキーを使って「現在利用可能なモデル一覧」を取得し、最適なものを自動で選ぶロジックを実装（404エラー根絶）。
  • New デバッグ詳細表示: APIエラー時にHTTPステータスコードとメッセージ全文を表示するように変更。
v2.5 Fallback System & Batch Fixes
  • New Google翻訳フォールバック: AI翻訳がエラー（404/429等）になった際、処理を止めずにGoogle翻訳へ自動で切り替える機能を実装。
  • New リアルタイム可視化: プログレスバーにフォールバック発生回数をリアルタイムで表示。
  • Fix バッチファイル安定化: 日本語コメントによる文字化け、& 記号による構文エラー、クリップボード誤爆問題を修正（choiceコマンド導入、英語UI化）。
v2.0 AI Integration
  • New Gemini AI搭載: 単語置換ではなく、JSONをまとめてAIに投げ、文脈（Minecraft用語）を考慮した翻訳を実現。
  • New バージョン自動検知: Mod内の pack.mcmeta を解析し、最適なパックフォーマットを自動設定。
v1.0 Initial Release
  • New 基本機能: Modからの言語ファイル抽出、Google翻訳、リソースパック生成、キャッシュ機能。
  • New 環境構築: start.bat によるPython仮想環境(venv)の自動構築。
